## 第一处：碰撞判定里"尾巴算不算障碍"

**位置**：`game/snake-core.js` → `advance()` 函数

**它在做什么**

蛇要往前走一步，得先判断这一步会不会撞到自己。这里最容易写错的是**蛇尾到底算不算障碍**：

```js
const ate = !!(g.food && nx === g.food.x && ny === g.food.y);

// 不吃食物时尾巴这一帧会移走，所以尾格不算障碍；
// 吃食物时蛇变长，尾巴留在原地，尾格必须算障碍。
const limit = ate ? g.snake.length : g.snake.length - 1;
for (let i = 0; i < limit; i++) {
  if (g.snake[i].x === nx && g.snake[i].y === ny) return 'dead';
}
```

**为什么要分开处理**

想象一条蛇朝右走，尾巴在它正后方。如果蛇头原地绕一圈回到尾巴那一格——这是完全合法的走法，因为**在蛇头到达的同时，尾巴刚好离开这一格**。如果判定时把尾巴也算成障碍，这种正常的走法就会被判成"撞到自己"，游戏体验会很差。

但吃到食物的情况不一样：吃到食物蛇会变长一节，也就是说**尾巴这次不让位了，留在原地**。这时候蛇头再撞上尾格，就是真的撞到自己了。

所以判定的上限（`limit`）要根据这一步"吃不吃"来定：
- 不吃 → 只检查到倒数第二节（`length - 1`），放尾巴一马
- 吃 → 检查全部（`length`），尾巴也算墙

**我的理解（用自己的话重写）**

> 先对着空气讲一遍：
> 1. 蛇往前走一步的时候，尾巴那一格到底发生了什么？
> 2. 吃到食物时尾巴为什么不走了？这个变化为什么会影响判定？
> 3. 如果不管吃不吃都把尾巴当成墙，玩家会遇到什么怪事？

蛇每往前走一步，整条身体都会 __________，所以尾巴原来占的那一格会 __________。
也就是说，蛇头走进"尾巴刚才待的地方"其实是 __________ 的，因为在我到达的那一刻，
尾巴已经 __________ 了。

但如果这一步吃到食物，蛇会 __________，尾巴这一帧 __________，
这时候再撞上去就是真的撞到自己了。

所以代码里那个 limit（决定检查到第几节）要分两种情况：
不吃食物时只查到 __________（放尾巴一马），吃食物时要查到 __________（尾巴也算墙）。

## 第二处：AI 的"安全性检查"——为什么它不会把自己困死

**位置**：`game/snake-core.js` → `aiDecide()` 函数

**它在做什么**

这是整个 AI 最关键的一段。蛇决定往哪走之前，会先把四个方向各**模拟走一遍**，然后对每一个"未来的自己"做体检：

```js
const after = snake.map(s => ({ x: s.x, y: s.y }));   // 复制一份蛇身
after.unshift({ x: nx, y: ny });                      // 假装走了这一步
if (!ate) after.pop();

const blockedAfter = buildBlocked(after);
const space = floodFill(blockedAfter, after[0]);      // 洪水填充：还能走到多少格
const need = after.length;
const tailReachable = !!bfsPath(blockedAfter, after[0], after[after.length - 1]);

cands.push({ d, space, safe: space >= need && tailReachable });
```

体检标准有两条，**两条都满足才算安全**：

1. **活动空间够不够**：从新蛇头出发做洪水填充，数一数还能走到多少个空格。如果这个数字比蛇身长度还小，说明自己已经缩进一个小圈里了，就算暂时没撞死，几步之内也会窒息。
2. **退路还在不在**：从新蛇头出发，还能不能找到一条通往自己尾巴的路。尾巴一直在往前让位，只要能追到它，就说明还有一个"能一直绕下去"的循环，不会被彻底封死。

**为什么必须做这两条检查**

如果只做"每次朝离食物最近的格子走"这种贪心策略，短蛇时看起来完全没问题，但蛇一长就会出事：它可能为了抄近路吃一个食物，把自己绕进一圈身体围成的死角里——食物是吃到了，但下一个食物永远走不到了。这在实测里通常发生在吃到第 5~8 个食物的时候。

加上体检之后，AI 会主动放弃"看起来近但吃完就没退路"的食物，转而先绕一圈把身体舒展开，等安全窗口出现了再吃。这就是它能把达标率做到 100% 的原因。

**兜底顺序也很重要**

体检完之后不是直接取"空间最大"的方向，而是按优先级挑：

1. 能吃且安全 → 吃
2. 在到食物的最短路径上且安全 → 追
3. 追尾巴且安全 → 追尾
4. 以上都不行 → 取空间最大的方向，多活几步

没有安全选项时（`pool` 会退回全部候选），说明已经是死局，这时也只能选"活得最久"的那个。

**我的理解（用自己的话重写）**

> 先对着空气讲一遍：
> 1. 用一句大白话说，"洪水填充"在这里其实是在数什么？（提示：就像往地上倒水）
> 2. 为什么"还能摸到自己的尾巴"就说明还有活路？
> 3. 只数空格、不看尾巴，会漏掉什么情况？

## 附加一处：BFS 距离场的方向（我踩过的坑）

虽然任务书只要求讲 2 处，但这一处我觉得最值得记下来，因为它是"看着对、跑起来全错"的典型。

**想做什么**：判断蛇头的某个相邻格是不是"朝食物更近了一步"。

**第一版写错的地方**：从蛇头出发做 BFS 得到距离场，然后判断 `dist[相邻格] === dist[食物] - 1`。

**为什么错**：相邻格到蛇头的距离恒等于 1，而食物可能在十几步外，`1 === 13 - 1` 永远不成立。结果就是"沿最短路追击"这条规则从来没被触发过，AI 每次都掉到兜底分支去。

**正确做法**：**从食物出发**做 BFS，得到一张"离食物还差几步"的距离表，再看蛇头的相邻格哪个表值比蛇头小 1。这样那个格子在几何上就真的位于通往食物的最短路径上。

一句话总结：**判断"往哪边走离目标更近"，距离场必须从目标向外算，不能从自己向外算。**

根本比不出哪个更近——这就是我第一版达标率 0% 的原因。
